# Странноватое дело — бриф уровня

**Статус:** одобренные предметные ассеты и новая иконка темы перенесены в игру. Пользователь проверяет обновлённые улики и финальную раскладку уровня.

## Подтверждённые решения

| Тема | Решение |
| --- | --- |
| Название | «Странноватое дело» |
| Поле | Одна доска 12×12; уникальность строк и колонок действует глобально для обоих миров |
| Миры | Обычный мир — строки 1–6; потусторонний — строки 7–12 |
| Лука и Ида | Пара с симметрией 180° вокруг центра: `(строка, колонка) → (13 − строка, 13 − колонка)` в координатах с единицы |
| Вращение | В потустороннем мире разворачиваются на 180° предметы и подписи зон; персонажи, подсказки и элементы интерфейса остаются читаемыми |
| Границы зон | Проверяются только между соседними зонами одного мира; переход через границу миров не считается границей зон |
| Обозначение зон | `М` и `ПМ` — Машина и Потусторонняя машина, не мастерская |
| Числовые улики по зонам | Не использовать в этом уровне |
| Общая улика | «Все персонажи на гласную букву находились в одном мире — обычном или потустороннем.»; должна давать полезный дедуктивный шаг, а не быть очевидной или избыточной |
| Иконка темы | Светлый дом с велосипедом и повёрнутая на 180° тёмная копия ниже, чтобы показать пару миров |
| Пустые зоны | Облако и туча планируются пустыми; улику об их пустоте добавлять только если она нужна для решения |
| Визуальный контраст миров | Для потустороннего мира предложен тёмно-бордовый tint `#7B2431`; проверить контраст с текстурами и объектами |

## План улик и дедукции

| Требование | Приоритет | Проверка |
| --- | --- | --- |
| Одна обязательная общая авторская улика: А, Е и И находятся в одном мире | Жёсткое | Утверждение уровня считает отдельные группы общих улик и проверяет эту группу; отдельная проверка-абляция подтверждает, что без неё дедукция действительно ослабевает. Возможная улика о пустых облаке и туче считается второй отдельной группой и остаётся необязательной |
| Числовые улики по населённости парной зоны не использовать | Жёсткое | Утверждение уровня запрещает `zoneExactCount` |
| Личные улики: цель 1–2 на персонажа, максимум 3; четвёртая не допускается | Жёсткий максимум, гибкая цель | Утверждение уровня проверяет число личных улик на каждого персонажа; `checkPuzzleQuality` проверяет полностью зафиксированных персонажей |
| Виктор — единственный выводимый убийца; известную жертву не использовать для косвенной фильтрации подозреваемых | Жёсткое | `checkMurdererEpistemics`: мир авторского убийцы — `PROVEN_UNIQUE`, все остальные варианты убийцы — `NO_SOLUTION`; тест проверяет отсутствие личных улик, раскрывающих жертву или связывающих других персонажей с ней |
| Пустые облако и туча | Гибкое | Утверждение карты проверяет размещение; отдельную улику о пустоте добавлять только если она нужна для решения |
| Форма зон | Критерий качества | Визуальная проверка: ступенчатые/ломаные границы и разнообразные формы, а не четыре одинаковые прямоугольные зоны |
| Машинные зоны | Жёсткое | Проверка level-data утверждает, что парное семейство `machine` имеет подписи «Машина» и «Потусторонняя машина», обе зоны используют `cobble` |
| Крона дерева | Жёсткое | Проверка level-data утверждает ровно 16 feature-клеток в каждом мире и равенство потустороннего набора повороту обычного на 180° |

Предполагаемая цель игрока — определить Виктора по авторским уликам и стандартному правилу сцены преступления. Хелен известна как жертва; используется только стандартная строка «Жертва находилась наедине с убийцей». Не добавлять авторские подсказки о Хелен или отношения других персонажей к жертве. Специально заданной приманки нет: подозрение должно следовать из улик, без предварительно выбранного ложного подозреваемого.

Текущая общая улика про А, Е и И действительно влияет на дедукцию: без неё solver находит альтернативу, в которой Алексей оказывается в обычном мире. Общий список также содержит пояснение «Обозначения зон в подсказках могут быть как из обычного мира, так и из потустороннего.»; это информационная заметка, она не участвует в solver.

По последнему QA удалены улики про булыжную мостовую Алексея и Карины, крону дерева Билла, дерево Галины, баскетбольную ось Джимми, потустороннюю машину Евгения, соседство Жанны с коробкой и скалу Луки. Улика Карины теперь прямо говорит «Карина находилась в машине.» У Виктора и Евгения нет личных улик, прямо называющих потустороннюю зону. Чтобы сохранить баланс типов и не возвращать точные позиционные подсказки, улика Билла о велосипеде ослаблена до общего ряда/колонки, а улика Галины о позиции относительно Джимми заменена на связь с баскетбольным мячом по ряду/колонке.

Для family-aware семантики соседства обеих зон-деревьев добавлена улика «Жанна находилась севернее Виктора.». Она устраняет альтернативные расстановки и сохраняет авторское решение `PROVEN_UNIQUE`. По прямому согласованию пользователя принято точечное исключение баланса для `relativePosition`: 5 из 21 улики (23,8%); другие критерии качества, включая нулевой бюджет полностью закреплённых персонажей, продолжают проверяться.

## Критерии приёмки

### Обязательные

- [x] Карта, границы зон, роли и координаты персонажей сверены с `osd.png`; строки, колонки и симметрия проверены.
- [x] Предложенная расстановка предметов предварительно принята как стартовая; позиции можно корректировать по результатам предпросмотра и solver.
- [x] Уровень имеет размер 12×12 и ровно 12 персонажей; каждый занимает отдельную строку и отдельную колонку на всей доске.
- [x] Лука и Ида стоят в клетках, связанных преобразованием `(r, c) → (13 − r, 13 − c)`.
- [x] Семейство машин подписано «Машина» / «Потусторонняя машина»; кроны содержат по 16 клеток с точной симметрией 180°.
- [ ] Потусторонний вариант визуально отличим, но подписи зон и предметы вращаются отдельно от персонажей, текста подсказок и интерфейса; обычный мир не получает потусторонний tint.
- [x] Границы зон не вычисляются между мирами. Числовых улик, считающих людей в одной зоне или в паре зон, в этом уровне нет.
- [x] А, Е и И находятся в одном мире; есть одна обязательная общая авторская улика для этой группы. Тест с удалённой уликой подтверждает альтернативное решение. Возможная отдельная улика о пустых облаке и туче остаётся необязательной.
- [x] Личных улик у каждого персонажа не больше трёх; цель — одна-две. Четвёртая улика не допускается; полностью зафиксированных личными уликами персонажей нет.
- [ ] Числовых улик по населённости зон нет; общая подпись парной зоны сама по себе не объединяет подсчёты миров.
- [ ] Используется только стандартная улика «Жертва находилась наедине с убийцей»; личные улики не раскрывают статус Хелен и не связывают подозреваемых с жертвой.
- [x] Убийца — Виктор, жертва — Хелен; правильная конфигурация определяется без альтернативного убийцы.
- [x] Предметы не перекрывают персонажей и друг друга; полиомино имеют допустимую форму, а каждый сегмент учитывается в занятости.
- [x] Занято 77 клеток предметами и особенностями пола; новых исключений из порога плотности не добавлено.
- [x] Ни один персонаж не оказывается полностью зафиксирован подсказками.
- [x] Улики решаемы solver'ом; решение уникально. `checkMurdererEpistemics` возвращает `PROVEN_UNIQUE` для Виктора и `NO_SOLUTION` для каждого альтернативного убийцы.
- [x] Пользователь одобрил арт; соответствующие ассеты велосипеда, гирлянды, переносной рации и темы перенесены из `art/` в игру.
- [ ] Пользователь проверил итоговую расстановку гирлянд в игровых домах/деревьях, читаемость стволов и фонарей, а также дедукцию по обновлённым уликам.

### Условные

- [ ] Если облако и туча остаются пустыми, подсказка об этом добавляется только при реальной необходимости для дедукции и после проверки поддержки нулевого количества линтером и solver'ом.
- [ ] Если предлагаемая расстановка предметов корректируется при визуальной сверке, повторно проверяются занятость, коллизии, формы предметов и порог 40%.

## Технические зависимости для реализации

- Текущая модель уровня не связывает зоны в пары миров; потребуется явная семантика мира/пары зон либо эквивалентное представление без изменения поведения существующих уровней.
- `letterGroupRoom` ограничивает персонажей одной комнатой; общая улика потребует ограничения «один мир».
- Потребуются корректное отображение пар зон в общей подписи подсказки и поворот подписи/предмета на 180° только в потустороннем мире.
- Плотность проверяется как сумма клеток предметов и особенностей пола в `tools/solver/acceptance.ts`; ID нового уровня не должен попадать в список исключений.

## Порядок дальнейшей работы

1. Карта и персонажи сверены с `osd.png`; предметная таблица и решения предварительно приняты как база реализации.
2. Учесть согласованное отсутствие заданной приманки и после проверки результата вносить предметные/сюжетные корректировки по необходимости.
3. Реализована поддержка пар миров/зон, общей улики, текстур и вращения ассетов.
4. Уровень проходит solver/линтер без исключений плотности и полностью зафиксированных персонажей.
5. Ассеты собраны в preview; после пользовательского ревью перенести утверждённые файлы в `src/assets/`, затем запустить `npm run verify`.
