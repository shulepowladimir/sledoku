# Библиотека арта: конвенция для дизайнера

Игра собрана вокруг реестра: **имя файла = ключ иконки**. Достаточно положить файл в нужную
папку — ассет автоматически обновится на всех уровнях, в меню и в ростере. Кода писать не нужно.

Полный список ключей с названиями и уровнями: [icon-reference.md](./icon-reference.md)
(регенерируется `npm run audit-icons`).

## Как смотреть результат

1. `npm run dev` → http://localhost:5173/?gallery — галерея всех ассетов
   (размеры 18/40/64px × светлый/тёмный/текстурный фон, статусы «дизайн/fallback»).
2. `npm run audit-icons` — консольный отчёт покрытия + обновление reference-документа.

## Папки

| Папка | Что кладём | Формат |
| --- | --- | --- |
| `src/assets/icons/items/` | иконки предметов (`plane.svg`, `windsock.svg`, …) | SVG |
| `src/assets/icons/themes/` | иконки тем главного меню (`airport.svg`, `zoo.svg`, …) | SVG |
| `src/assets/icons/persons/` | архетипы персонажей (`person-m-01.svg`, `person-f-02.svg`) | SVG |
| `src/assets/textures/` | текстуры пола (`wood.svg` или `wood.png`) | SVG или PNG |

Файл с ключом не найден → игра рисует текущую встроенную иконку (fallback). Поэтому можно
присылать партиями — ничего не ломается. Полное покрытие категории (см. audit) → встроенные
иконки категории удаляются из кода.

## Иконки предметов и тем

- Квадратный SVG, единый **viewBox 96×96** для всех; контент в safe area ≈ 84×84
  (по 6px полей — иконки не должны «упираться» в края).
- Имя файла — строго существующий ключ (см. reference). Новые ключи — только через разработку.
- Читаемость от **18px** до ~180px: минимальная толщина детали ≈ 3px в масштабе 96×96;
  силуэт должен узнаваться в чёрно-белом виде.
- Предметы рендерятся поверх 20 текстур пола — проверяйте в галерее на всех трёх фонах.
- Для «сидимых» предметов (стул, диван, лошадь, трон…): узнаваемая посадочная зона по центру-низу.
- Чистота файла:
  - без растровых вставок, текста, шрифтов;
  - без blend modes и фильтров (blur, shadow);
  - strokes расширены в контуры (expand strokes);
  - градиенты и клипы — можно; `id` внутри файла — уникальные с префиксом ключа
    (файлы инлайнятся на одну страницу: `planeGradient1`, а не `gradient1`).
- Ориентир по весу: **≤ 10 КБ** на файл.

## Темы меню

Те же требования. Композиция — «обложка уровня»: один узнаваемый образ, без мелких деталей
(рендер 40–64px). Темы `airport` и `zoo` по умолчанию переиспользуют иконки предметов
`plane`/`penguin`; собственный файл темы имеет приоритет.

## Текстуры пола

- Бесшовный квадратный тайл: **SVG 256×256 или PNG 256×256** (сложные — 512).
  Бесшовность обязательна: проверяйте стык в галерее (превью 3×3 тайла).
- Тайл рендерится в клетке 64×64: не перегружать деталями, без крупных тёмных пятен —
  поверх стоят фигурки персонажей и предметы.
- `stairs` — горизонтальные ступени (верх тайла = дальняя часть), `cliff` — скальная порода.
- SVG приоритетнее PNG с тем же именем.

## Архетипы персонажей

- Именование: `person-m-01.svg` … `person-m-08.svg` (мужские), `person-f-01.svg` … (женские).
  Нумерация с `01`, последовательная.
- **Одежда красится игрой**: фигура одежды — отдельной фигурой с заливкой
  `fill="var(--person-clothing, #888)"`. Цвет придёт из геймплея (цвет персонажа — игровая
  информация). Всё остальное (кожа, волосы, детали) — запечено в файле.
- viewBox 96×96, силуэт в полный рост, различим в ч/б, читаемость от 18px.
- Архетип выбирается игрой детерминированно по id персонажа — набор должен быть
  разнообразным внутри гендера. Допустимо поставлять гендеры партиями (м/ж независимо).
- Аудит проверяет: имя по конвенции + наличие `var(--person-clothing)` в файле.

## Приёмка

1. Пилотная партия (5–10 иконок) — согласование стиля до массового производства.
2. Каждая партия: файлы в папки → смотрим `/?gallery` → правки.
3. Готовность категории = `npm run audit-icons` показывает 100% покрытие без orphan-файлов.
